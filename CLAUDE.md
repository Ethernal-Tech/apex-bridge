# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Apex Bridge validator and relayer software in Go: moves value between Cardano chains (`prime`,
`vector`) and an EVM chain (`nexus`) through a bridge smart contract on a Blade bridge chain.

## Commands

```shell
make build        # go build -o apex-bridge, with commit/branch/time injected into versioning/
make lint         # golangci-lint run --config .golangci.yml
make unit-test    # go test -tags testenv -race -shuffle=on ... over every package except e2e (20 min timeout)

# One package or one test (keep -tags testenv: some files only compile with it)
go test -tags testenv -race ./batcher/batcher/...
go test -tags testenv -race -run TestBatcherExecute ./batcher/batcher/
```

- Go 1.23.1 (CI pins it). `.golangci.yml` is a golangci-lint v1 config; it also runs the
  project's own `gorules/` ruleguard rules through gocritic.
- `github.com/Ethernal-Tech/cardano-infrastructure` is private: set `GOPRIVATE` and the git
  `insteadOf` rewrite from the README before `go get`.
- `go.mod` replaces `gouroboros` with an Ethernal fork (raised CBOR nesting limit). Keep that
  `replace` when bumping dependencies: replaces in dependencies are not inherited.
- `contractbinding/*.go` is generated by `abigen` from the `apex-bridge-smartcontracts` and
  `apex-evm-gateway` Hardhat artifacts (steps in the README).

## Architecture

- `validator-components` (`validatorcomponents/validatorcomponents/validatorcomponents.go`) wires
  everything a validator runs:
  - **Oracles** index source chains (Cardano via cardano-infrastructure's indexer, EVM via
    blockchain-event-tracker), parse bridging metadata, run tx processors, and submit claims to
    the bridge contract through `oracle_common/bridge`.
  - **Batchers** (one per destination chain under `batcher_manager`) read confirmed
    transactions from the bridge contract, build the destination batch through a
    `core.ChainOperations` implementation (Cardano multisig tx or EVM gateway payload), sign
    it, and submit the signature back to the bridge contract.
  - **Relayer imitator** tracks batch submission state locally; `validatorobserver` pushes
    validator-set changes into the batchers.
  - **API** (`validatorcomponents/api`, gorilla/mux, API-key auth) serves bridging-request
    state, oracle state and settings.
- `relayer` takes confirmed, fully signed batches from the bridge contract and submits them to
  the destination chain (Cardano or EVM `ChainOperations`).
- Each component keeps its own BoltDB under `database_access/`.
- Tests use hand-written testify mocks next to the interfaces (`*_mock.go`, `test_mocks.go`).

## Verification

- Before a push: `make lint` (the fast gate).
- Before a PR: `make lint build` (the full gate).
- Tests: `go test -tags testenv -race` on the touched packages; `make unit-test` for the whole
  tree (up to 20 min).
- Then ask Claude to run its verify skill: a Scenario, Layer, Outcome table from real output.
- Results come from real output; anything not run is reported as not run.

## Rules

- Conventional commits, `<type>(<scope>): <summary>`. Why: the squash commit takes the PR
  title, and a readable history is the project's record of changes.
- Claude verifies a task, then leaves its changes unstaged and names the files; the engineer
  commits them. Why: the engineer owns every commit.
- New environment variables go into `.env.example` with a name and no value. Why: secrets stay
  out of git and out of the model's context.
- Adopt the newest stable release of a dependency; fix the code instead of pinning back. Why:
  old versions pile up security fixes that are hard to catch up on.

## Don't

- Don't commit, push or open a PR unless asked; never push to `main` or force-push.
- Don't merge with a red or missing required check.
- Don't read, print or commit `.env` files.
- Don't describe unverified behaviour as verified.
